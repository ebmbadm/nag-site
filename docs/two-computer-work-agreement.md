# Соглашение о совместной работе с novikamps.com

Статус: на согласование между двумя компьютерами
Дата: 2026-08-04

## 1. Цель

Оба компьютера работают с одной и той же локальной копией сайта NOVIK, одними
правилами Git и одним порядком публикации. Рабочий сайт меняется только после
согласованного merge в `main`.

## 2. Единый локальный путь

На каждом компьютере должна быть своя независимая локальная рабочая копия,
расположенная строго здесь:

```text
C:\NOVIK\nag-site
```

Синхронизация между двумя копиями выполняется только через общий удалённый
Git-репозиторий, а не через общий каталог. До подтверждения работы из нового
пути старую копию не удалять. После переноса на каждом компьютере проверить:

```powershell
git -C C:\NOVIK\nag-site status --short --branch
git -C C:\NOVIK\nag-site remote -v
```

Съёмный диск `D:` используется только для передачи файлов. Работать,
коммитить, запускать сервер или собирать проект прямо на `D:` запрещено.

## 3. Локальные данные

| Что | Единое место | Правило |
| --- | --- | --- |
| Код сайта | `C:\NOVIK\nag-site` | Это единственная рабочая копия. |
| Секреты | `C:\NOVIK\nag-site\.env` | Не добавлять в Git, PR, чат, скриншоты или общий архив. |
| Материалы «История NOVIK» | `C:\NOVIK\nag-site\reference\history-novik-2026-08-01` | Справочный локальный архив; не добавлять в Git без отдельного решения. |
| Временные файлы | `C:\NOVIK\nag-site\work` | Не коммитить, если это не оговорено отдельно. |

Перед очисткой носителя убедиться, что локально существуют `.env`, исходный
PDF, HTML-версия, изображение корабля и журналы передачи.

## 4. Репозиторий и ветки

Основной удалённый репозиторий:

```text
https://github.com/ebmbadm/nag-site.git
```

| Назначение | Правило |
| --- | --- |
| `main` | Единственная ветка публикации. В неё не работать напрямую. |
| `agent/<задача>` | Отдельная ветка для одной согласованной задачи. |
| Draft PR | Единственный путь для проверки изменений перед merge. |

Предлагаемая схема имён для согласования:

```text
agent/history-novik       — доработка раздела «История NOVIK»
agent/catalog-<тема>      — отдельная задача по каталогу
agent/site-ops-<тема>     — инфраструктура, документация или локальная среда
agent/fix-<тема>          — локальное исправление ошибки
```

Текущую ветку `agent/novikamps-local-bootstrap-publish` не переименовывать и
не удалять без отдельного согласования: она связана с уже существующим Draft
PR. После согласования эта ветка остаётся исторической веткой настройки, а
новые задачи начинают в ветках по схеме выше.

## 5. Порядок работы на двух компьютерах

1. Перед началом работы выполнить `git fetch origin`, проверить текущую ветку
   и статус, затем получить согласованную ветку только fast-forward способом:

   ```powershell
   git pull --ff-only
   ```
2. В один момент времени редактирует и делает push только один компьютер.
3. После завершённого проверенного шага сделать небольшой осмысленный коммит.
4. Сразу отправить коммит в удалённую ветку: это контрольная точка для обоих
   компьютеров.
5. Перед передачей работы второму компьютеру первый должен сделать commit и
   push; второй — `git fetch origin`, переключиться на нужную ветку и
   выполнить `git pull`.
6. Не применять `git reset --hard`, принудительный push или удаление ветки без
   явного согласования обоих участников.

## 6. Проверка и публикация

Для изменений приложения перед push выполнять относящиеся к задаче проверки:

```powershell
npm run lint
npm test
npm run build
```

Публикация происходит так:

```text
локальная ветка → push → Draft PR → проверка → согласованный merge в main → CI/CD → рабочий сайт
```

Не запускать прямой SSH-деплой. По указанию разработчика CI/CD выполняет
публикацию автоматически после merge в `main`. Push в ветку и Draft PR не
изменяют `novikamps.com`.

## 7. Секреты и формы

- `.env` обязателен только локально и на сервере; он игнорируется Git.
- `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, Telegram-настройки и
  параметры деплоя должны быть заполнены до проверки форм.
- `RESEND_API_KEY` необязателен для сборки и публикации. Без него не уходят
  email-уведомления, но сайт и Telegram-уведомления работают при наличии
  остальных настроек.
- Прямой SSH-доступ пока не подтверждён; для стандартного процесса через PR
  он не требуется.

## 9. Локальный доступ к NAGHUB на основном компьютере

Ярлык рабочего стола `Остатки NAGHUB` открывает опубликованную страницу
остатков:

```text
https://my-app-alpha-seven-30.vercel.app/listings/stock
```

Не использовать в этом ярлыке `http://localhost:3001`: это адрес отдельного
локального dev-сервера, а не работающей панели NAGHUB. После запуска NAGHUB
на основном компьютере достаточно открыть ярлык и использовать ту же
авторизованную браузерную сессию. На втором компьютере выполняется только
проверка и отчёт; ярлык и синхронизацию eBay там не настраивать.
